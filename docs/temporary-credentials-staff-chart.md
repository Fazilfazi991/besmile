# Temporary clinician credentials and staff chart

External account creation now generates a unique server-side credential using 24 cryptographically random bytes (192 bits). The immediate authorized response returns it once. The manager sees a masked field with Copy, Dismiss, and the warning “This temporary password will not be shown again.” No credential is stored in application tables, request records, Auth metadata, audit events, browser storage, or logs. Responses require the same origin and use private/no-store headers.

Existing-account regeneration requires the existing `outsourced_clinicians.manage` permission. A reservation binds actor, clinician, linked Auth/profile UUID, approved email, and request UUID. Only active, enabled, confirmed outsourced identities that still require onboarding and have never signed in qualify. Completed requests never update Auth or return a credential. Pending requests and uncertain Auth/audit outcomes require manual review. The server rechecks live Auth and database eligibility immediately before a password-only Admin API update. Audit records contain only actor, target identity, clinician ID, action, and timestamp.

Supabase Auth has no conditional password-update API tied to `last_sign_in_at`. Database reservations serialize this workflow, but cannot atomically cover a concurrent Auth sign-in. Operators must recheck eligibility for each approved reset and stop for any sign-in history or changed account state. Do not automatically retry an uncertain reset.

Mandatory password onboarding rejects reuse of the current temporary credential. An Auth “same password” error never counts as completion. If a private-password update succeeds but the completion RPC fails, the user must choose another new password to retry. Internal legacy provisioning remains unchanged.

Operational internal staff statuses remain `active`, `intern`, and `probation`. The migration preserves existing role, bundle, and grant rules while correcting active-only internal eligibility. It adds no administrator grants and changes no employment classification. Team attendance and authorized workspace employee search use the same operational statuses. Chat summary timeouts use the existing membership-scoped fallback; permission denials do not.

`organization_directory()` remains internal-only for employee and HR selectors. The chart reads the new classified `organization_people_directory()` projection. Eligible linked external clinicians appear in a separate read-only Online Psychologists section. Pending onboarding does not grant them workspace access. Cards have an external label, no employee identifiers or payroll/attendance status, and no employee HR links. Existing clinician managers can navigate to clinician management. External entries never enter the employee hierarchy editor. No manager relationships are written for visualization.

Migration: `20261006145005_clinician_temporary_credentials_and_organization_people.sql`. It is forward-only and guarded against unexpected installed permission/provisioning definitions. It also preserves existing professional information when omitted from a provisioning payload. The private request table stores workflow metadata only.

The candidate was tested against QA with disposable accounts. Production remains read-only until separate authorization for release and any exact account resets. The private release report and inventory are in ignored local release evidence and must not be committed. Existing internal Aiswarya and the separate unlinked Auth account remain untouched.
